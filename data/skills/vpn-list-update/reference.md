# Справочник навыка vpn-list-update

Детальный контракт формата каталога и реестра источников. Читать перед изменением формата, добавлением группы или внешнего источника, при разборе ошибок validate.

## Контракт catalog.json

Корневые поля:

| Поле | Тип | Смысл |
|------|-----|-------|
| `schema` | число | Версия схемы контракта; единственная допустимая - `1` |
| `version` | строка | Версия каталога в формате `yymmdd`; поднимается при любом изменении содержимого |
| `groups` | объект | Группы записей; ключи - фиксированный набор групп |

Группы контракта: `youtube`, `telegram`, `meta`, `twitter`, `discord`, `payments`, `ai`. Новая группа - изменение контракта: сначала правка README и этого справочника, потом каталог.

Запись группы - объект с обязательными полями `value`, `kind`, `source`, `added` и опциональным `comment`:

| Поле | Тип | Смысл |
|------|-----|-------|
| `value` | строка | Домен (`example.com`, нижний регистр, без схемы и пути) или подсеть в канонической записи CIDR (`203.0.113.0/24`) |
| `kind` | строка | `domain`, `cidr_v4` или `cidr_v6` - должен соответствовать формату `value` |
| `source` | строка | `manual` для ручных записей или `id` внешнего источника из sources.json |
| `added` | строка | Дата добавления записи, `yymmdd` |
| `comment` | строка | Произвольный комментарий; допускается пустая строка |

Правила содержимого:

- Только добавление: внешние источники и ручные правки добавляют записи; удаление и изменение существующих не допускается
- Подсети в канонической форме (без битов хоста), IPv4 не шире `/16`, IPv6 не шире `/32`
- Записи внутри группы сортированы по `kind`, затем `value` - обогащение пересортировывает группу целиком
- Значение уникально по всему каталогу: дубликат внутри группы и совпадение между группами - ошибка validate
- `version` не старше максимальной даты `added`; при ручной правке поднимать версию вручную

## Реестр источников sources.json

Файл лежит в корне каталога навыка. Обогащение читает только источники с `enabled: true`.

| Поле | Тип | Смысл |
|------|-----|-------|
| `id` | строка | Уникальный идентификатор источника; попадает в поле `source` записей |
| `url` | строка | Адрес текстового списка: одна запись на строку, пустые строки и `#`-комментарии игнорируются |
| `group` | строка | Группа каталога, в которую добавляются записи источника |
| `kind` | строка | `domain` или `cidr` - формат записей источника; версия IP для `cidr` определяется по значению |
| `enabled` | булево | Включен ли источник; отключенный пропускается с сообщением |

Порядок добавления нового источника:

1. Проверить доступность URL и формат строк (домены или подсети, одна на строку)
2. Добавить объект в `sources` с осмысленным `id` вида `<origin>-<service>-<kind>`
3. Запустить enrich; убедиться по отчету, что добавления уместны, затем validate

Текущие источники - посервисные списки репозитория `itdoginfo/allow-domains` (домены из `Services/`, подсети из `Subnets/IPv4/` и `Subnets/IPv6/`). Группа `payments` внешних источников не имеет - наполняется вручную.

## Лимиты обогащения

| Параметр | По умолчанию | Флаг enrich.py |
|----------|--------------|----------------|
| Таймаут загрузки источника | 30 сек | `--timeout` |
| Минимальная длина префикса IPv4 | `/16` | `--min-prefix-v4` |
| Минимальная длина префикса IPv6 | `/32` | `--min-prefix-v6` |
| Максимум записей в группе | 5000 | `--max-entries` |

Более широкие подсети и записи сверх лимита отбрасываются с указанием числа в отчете. `--dry-run` показывает, что было бы добавлено, без записи файла.

## Поведение при сбоях

- Недоступный источник: строка `[!]` с причиной, источник пропускается, записи остальных источников сохраняются, код возврата 1
- Некорректная строка в источнике: пропускается и считается в отчете как `некорректные`
- Запись файла атомарная: временный файл в каталоге каталога и замена; при ошибке записи старый каталог не повреждается
- При отсутствии новых записей файл каталога не перезаписывается

## Коды возврата скриптов

| Код | Смысл |
|-----|-------|
| 0 | Успех: каталог валиден или обогащен без сбоев |
| 1 | Ошибка исполнения: ошибки валидации, недоступный источник, ошибка данных или записи |
| 2 | Ошибка использования: отсутствуют обязательные аргументы |

Вывод скриптов - строки `YYYY-MM-DD HH:MM:SS [маркер] сообщение`; маркеры по `project_standards.md` 04.02: `[i]` - информация, `[!]` - ошибка, `[*]` - предупреждение.
