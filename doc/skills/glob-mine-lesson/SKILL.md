# Фиксация урока в журнал

Добавляет переносимый опыт в журнал уроков `data/lessons.md` репозитория (канон журнала - `project_standards.md`, раздел 01.01.07). Журнал - точка накопления знаний для обогащения хаба стандартов: сбор кандидатов из проекта выполняет навык `hub-mine-knowledge` в хабе. Навык только добавляет записи и больше ничего в репозитории не меняет.

## Когда использовать

- Пользователь просит зафиксировать урок, записать урок или опыт, отметить прием
- В ходе работы обнаружено переносимое знание: прием, ловушка библиотеки или среды, неочевидное решение - то, что пригодится в других проектах
- Пользователь явно вызвал навык по имени `glob-mine-lesson`

## Инструкция

1. Прочитать `doc/standards/_index_standards.md` и применять найденные стандарты в своей работе; требования к тексту записи - `project_standards.md` (раздел 04.03)
2. Проверить наличие `data/lessons.md`; при отсутствии - создать по шаблону шапки ниже
3. Сформулировать пару «контекст - урок»:
   - контекст - конкретика ситуации: файл и строка, коммит, задача, машина, версия; допустимы любые детали - журнал остается внутри репозитория
   - урок - обобщенная формулировка для класса ситуаций (архитектура, семейство ОС, диапазон версий библиотеки, класс устройства); без имен машин и пользователей, адресов и путей конкретной машины
4. Проверить тест ценности: воспроизведется ли урок в следующем проекте. Знание, привязанное только к данному экземпляру среды, - кандидат в проектный оверрайд (`doc/specs/overrides.md`, раздел 01.01.02), а не в журнал; предложить пользователю этот вариант вместо записи
5. Определить класс урока: правило (норма, которой не хватает в пакете стандартов), пример (эталонный фрагмент кода или конфигурации), словарь (пополнение словарей текста), навык (повторяемая процедура)
6. Добавить запись в конец журнала по шаблону; номер - следующий сквозной
7. Сообщить пользователю номер и суть записи; коммит - по запросу пользователя или правилам репозитория

## Шаблоны

Шапка файла при создании:

```markdown
# Журнал уроков

Переносимый опыт проекта; канон - project_standards.md, раздел 01.01.07
```

Шаблон записи:

```markdown
## <NN>. <title>

- Дата: <YYYY-MM-DD>
- Источник: <source>
- Контекст: <context>
- Урок: <lesson>
- Класс: правило | пример | словарь | навык
- Кандидат в хаб: да | нет
```

## Примеры

1. Пользователь: «зафиксируй урок» после решения проблемы с драйвером -> агент записывает контекст с классом устройства и версией драйвера, урок - требование флага для всего класса устройств на данной архитектуре; класс «правило», кандидат в хаб - да
2. Агент нашел обходное поведение библиотеки, не описанное в документации -> предлагает пользователю зафиксировать урок, после подтверждения добавляет запись с классом «пример»

## Ограничения

- Навык только добавляет записи в `data/lessons.md`; существующие записи не правятся и не удаляются
- Архивация журнала - только по явному запросу пользователя
- Удаление файлов и папок репозитория - перенос в `.trash/<slug>_<YYYYMMDDHHMM>/` (карантин, `project_standards.md` 01.01.06), а не удаление; чистить `.trash/` только по явному запросу пользователя
