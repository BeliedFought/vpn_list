# Канон разработки и проверки навыков. Версия 4.16.0

Дополнение к `skill_plain_standards.md` и `skill_anthropic_standards.md`: методика разработки навыка и проверки его поведения до публикации. Применяется при создании навыка и при правке существующего. Порядок принятия решений при отсутствии нормы - `project_standards.md`, раздел 07.06.

Структурные требования к навыку (frontmatter, расположение, тело, ресурсы) - в соответствующих skill-стандартах; настоящий документ задает правила описания для обнаружения и методику проверки поведения.

## 01.01. Область применения

*Обязательно.*

Правила применяются к любому навыку независимо от формата (plain-файл или каталог `SKILL.md`), при создании и при правке. Тип навыка (`hub_loc`, `hub_glob`, `pr_glob`, `pr_loc`) и категория на применение методики не влияют.

---

## 01.02. Обязательность

*Обязательно.*

- Правила описания (раздел 02) и структурные требования (раздел 03) обязательны для каждого навыка
- Проверка поведения (раздел 04) обязательна по классу навыка (раздел 04.01): для дисциплинирующих навыков - полностью, для остальных - в объеме микротестов формулировок и применения на новом сценарии
- Правка существующего навыка проверяется тем же порядком, что новый навык: изменение формулировки нормы способно ослабить навык

---

## 02.01. Назначение описания

*Обязательно.*

`description` - единственное поле, по которому агент решает, загружать ли навык. Оно отвечает на вопрос «должен ли я прочитать этот навык сейчас», а не «что навык делает внутри». Цель - попадание в выбор агента по реальному запросу.

---

## 02.02. Правила

*Обязательно.*

- Описание отвечает на «когда применять»: конкретные триггеры, симптомы, ситуации и ключевые слова (имена инструментов, типы ошибок, названия библиотек, симптомы сбоя)
- Третье лицо, без первого лица и без обращения к пользователю
- Форма упаковки: короткая фраза о назначении плюс условия применения (СТРУКТУРА описания - `skill_anthropic_standards.md`, раздел 02.03); пересказ процесса и пошаговой методики в описании запрещен
- Обоснование запрета: описание, пересказывающее порядок действий, становится коротким путем - агент следует описанию вместо чтения тела навыка. Наблюдение: описание вида «code review between tasks» приводило к одному ревью вместо двух, пока описание не сменили на условие применения без пересказа процесса
- Приоритет конкретики: симптом или ситуация важнее общего намерения. «При гонках, нестабильных тестах, плавающих результатах» вместо «для асинхронного тестирования»
- Для дисциплинирующего навыка в описание добавляются симптомы-предвестники нарушения: состояние, в котором агент склонен обойти норму (например «когда код уже написан до теста», «когда правка кажется слишком простой для проверки»)
- Лимиты: `description` - до 1024 символов, цель - менее 500; имя навыка - строчные латинские буквы, цифры, дефис, до 64 символов
- Без маркетинга и оценок («мощный», «удобный», «лучший»)

---

## 03. Структурные требования

*Обязательно.*

Сводка требований, детали - в skill-стандартах:

- Тело `SKILL.md` - до 500 строк; превышение выносится в ресурсы
- Тяжелый справочник (свыше 100 строк) и переиспользуемые скрипты - в отдельные файлы каталога; в теле - ссылка и условие чтения (progressive disclosure)
- Ссылки из тела - на один уровень вглубь; имя файла описательное
- Файл ресурса свыше 100 строк начинается с оглавления
- Кросс-ссылки на другие навыки - по имени навыка; `@`-ссылки не используются (форсируют загрузку контекста)
- Схема (flowchart) - только для неочевидной развилки или цикла, не для линейных шагов

## 04.01. Обязательность по классу навыка

*Обязательно.*

| Класс навыка | Проверка поведения |
| ------------ | ------------------ |
| Дисциплинирующий - норма, которую агент склонен обходить под давлением (порядок работы, запреты, обязательные шаги) | Обязательна полностью: сценарии давления, закрытие лазеек, повтор до устойчивости |
| Техника или паттерн - способ выполнения операции | Микротесты формулировок и применение на новом сценарии; сценарии давления - при наличии соблазна обойти |
| Чистый справочник - API, синтаксис, каталог команд | Не требуется; достаточно проверки попадания в выбор по описанию |

Микротесты формулировок (раздел 04.04) применяются к любому навыку, меняющему поведение агента.

---

## 04.02. RED-GREEN-REFACTOR

*Обязательно для дисциплинирующего навыка.*

Разработка навыка повторяет дисциплину тестов (`project_standards.md`, раздел 07.01, верификация):

- RED: прогон сценария без навыка. Зафиксировать поведение и рационализации агента дословно - это падающий тест, без него неизвестно, чему учить навык
- GREEN: минимальное тело навыка, закрывающее зафиксированные нарушения. Без запаса «на всякий случай». Повторный прогон того же сценария с навыком - агент соблюдает норму
- REFACTOR: новый обход - явный контр-аргумент, повтор прогона до устойчивости

Правило: у дисциплинирующего навыка нет проверки - нет навыка.

---

## 04.03. Сценарии давления

*Обязательно для дисциплинирующего навыка.*

Сценарий проверки строится на комбинированном давлении и требует выбора:

- Не менее трех давлений одновременно; сочетание сильнее единичного
- Конкретный выбор из вариантов (A / B / C), а не открытый вопрос: открытый вопрос агент пересказывает теорией
- Реалистичные ограничения и пути: время, последствия, существующие файлы - не абстрактный пример
- Побуждение действовать («что вы делаете»), а не рассуждать («что говорит навык»)
- Запись рационализаций дословно: они становятся таблицей рационализаций навыка

Типы давлений:

| Давление | Пример |
| -------- | ------ |
| Время | Авария, дедлайн, окно деплоя закрывается |
| Напрасные затраты | Много часов работы, жаль удалять |
| Авторитет | Руководитель или старший просит пропустить шаг |
| Экономика | Ставка - работа, повышение, судьба компании |
| Усталость | Конец дня, устал, хочется домой |
| Социальное | Не выглядеть догматиком |
| Прагматизм | «Быть прагматичным, а не догматичным» |

## 04.04. Микротесты формулировок

*Обязательно при изменении поведения агента.*

Быстрая проверка формулировки до полных прогонов:

1. Одна свежая выборка на вызов: отдельный вызов модели или однократный субагент; системный контекст - реалистичный (полное тело навыка или шаблон), пользовательское сообщение - задача, провоцирующая нарушение
2. Обязательная контрольная выборка без подсказки: если без подсказки нарушения нет, чинить нечего - правило не пишется
3. Не менее пяти повторов на вариант: одна выборка лжет
4. Каждое срабатывание читается вручную: автосчет по маске ловит цитаты и контрпримеры и искажает вывод
5. Разброс трактовок - метрика: устойчивая формулировка дает одинаковый результат; пять разных трактовок на пяти прогонах означают, что формулировка не связывает - форму сжимают до добавления слов

Микротесты проверяют формулировку; сценарии давления для дисциплины они не заменяют.

---

## 04.05. Форма под тип сбоя

*Обязательно.*

Форма правила подбирается под зафиксированный сбой: одна форма лечит свой класс сбоя и ослабляет другой.

| Сбой без навыка | Верная форма | Неверная форма |
| --------------- | ------------ | -------------- |
| Агент обходит норму под давлением | Запрет плюс таблица рационализаций и красные флаги | Мягкая рекомендация («предпочтительно», «по возможности») |
| Результат верный по смыслу, но неверный по форме | Позитивный рецепт: что результат есть, из каких частей, в каком порядке | Список запретов («не пересказывать», «не рассуждать») |
| Пропуск обязательного элемента | Структурный слот в шаблоне (обязательное поле) | Прозаичное напоминание рядом с шаблоном |
| Поведение зависит от условия | Условное правило, привязанное к наблюдаемому признаку | Безусловное правило с оговорками-исключениями |

- Оговорки-нюансы запрещены: формулировка «не делай X, если это не важно» переоткрывает торг и размывает правило; реальное исключение выражается отдельным условием на наблюдаемом признаке
- Оговорка-исключение не сужает область: «это не относится к блокам кода» продолжает подавлять блоки кода; правило перестраивается так, чтобы не доставать до исключения
- При прочих равных короче формулировка предпочтительнее: тело навыка перечитывается агентом многократно, длина - реальная стоимость

## 04.06. Закрытие лазеек и meta-тест

*Обязательно для дисциплинирующего навыка.*

На каждую новую рационализацию агента - четыре действия:

1. Явный запрет конкретного обхода в теле навыка
2. Строка в таблице рационализаций (обход - контр-аргумент)
3. Запись в списке красных флагов
4. Обновление `description` симптомом-предвестником

Meta-тест при неудаче: спросить агента, как переписать навык, чтобы верный выбор был однозначен. Три категории ответа и вывод:

- «Навык был ясен, я его проигнорировал» - документация ни при чем; усилить базовый принцип («нарушение буквы есть нарушение сути»)
- «Навык должен был сказать X» - пробел в тексте; вписать формулировку агента
- «Я не увидел раздел Y» - проблема структуры; сделать ключевое заметнее, вынести в начало

---

## 04.07. Критерии приемки

*Обязательно.*

Навык устойчив (bulletproof), если под максимальным давлением агент выбирает верный вариант, ссылается на раздел навыка, признает искушение, но следует норме.

Навык не готов, если: агент находит новые рационализации, спорит с нормой, изобретает «гибридные» обходы или просит разрешения, аргументируя за нарушение.

---

## 05. Чек-лист автора навыка

*Обязательно.*

- [ ] RED: сценарий без навыка прогнан, нарушения и рационализации зафиксированы дословно (дисциплинирующий навык)
- [ ] Описание: условия применения, конкретные триггеры и симптомы, без пересказа процесса; в пределах лимита (раздел 02.02)
- [ ] Форма правил соответствует типу сбоя (раздел 04.05): нет мягких рекомендаций вместо запретов и пересказа процесса вместо рецепта
- [ ] GREEN: тело навыка закрывает зафиксированные нарушения; повторный прогон дает соблюдение
- [ ] Формулировки микро-тестированы при изменении поведения: контрольная выборка без подсказки, не менее пяти повторов (раздел 04.04)
- [ ] REFACTOR: новые рационализации закрыты (раздел 04.06); прогон повторен
- [ ] Таблица рационализаций и список красных флагов присутствуют (дисциплинирующий навык)
- [ ] Структура: тело до 500 строк, тяжелые материалы в ресурсах, ссылки на один уровень (раздел 03)
- [ ] Навык найден по описанию и приводит к результату на реальном запросе
